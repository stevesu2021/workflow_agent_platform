“智能体”页面，在构建workflow智能体画布的“规划”页面，设计并开发“意图识别”组件。

以下是一份参考 Dify 和 百度千帆大模型平台 中意图识别（Intent Recognition）组件的设计理念与功能实践，结合低代码 Workflow 编排场景，整理而成的标准化 “意图识别组件”需求文档。该文档适用于自研可视化智能体（Agent）工作流系统。

意图识别组件需求文档  
版本：1.0  
适用系统：可视化 Workflow 编排平台（如 Dify / Coze / 千帆 类 Agent Builder）

一、组件概述

1.1 组件名称  
意图识别（Intent Recognition）

1.2 定位  
作为智能体（Agent）理解用户自然语言输入的核心路由节点，用于：
- 判断用户当前请求属于哪一类预定义任务；
- 提取关键参数（槽位）；
- 动态决定后续执行路径（如调用哪个工具、进入哪个子流程）。

1.3 设计原则
- 能力对齐：仅识别当前 Workflow 能力范围内（即已配置的 Output/Action 节点）的意图；
- 零训练门槛：无需标注数据或模型训练，通过示例+LLM 实现；
- 可解释 & 可调试：支持查看匹配结果、置信度、提取参数；
- 安全可控：不依赖外部 NLU 服务，基于平台 LLM 统一调度。

二、输入与输出

2.1 输入（Input）
字段   类型   来源   说明
user_input   string   上游节点（如 Start / User Message）   用户原始文本，必填

示例："帮我查一下订单 ABC123 的物流状态"

2.2 输出（Output）
字段   类型   说明
intent   string   匹配到的意图标识符（对应某个 Output 节点 ID 或自定义 key）

intent_name   string   意图可读名称（如 “查询订单”）

confidence   float (0.0–1.0)   匹配置信度，用于条件判断

slots   dict   提取出的结构化参数例：{"order_id": "ABC123"}

matched_node_id   string   （推荐）匹配到的下游目标节点 ID，便于直接路由

raw_response   dict   原始 LLM 返回内容（调试用）

⚠️ 若无匹配意图，intent = "unknown"，confidence ≈ 0，可配置是否走兜底流程。

三、意图定义方式（关键机制）

意图不由全局意图库定义，而是由 Workflow 中已存在的功能性节点反向生成。目前支持两种主流模式：

✅ 模式 A：基于 Output 节点自动推导（推荐，参考 Dify）
- 每个 Output 节点（或 Action 节点）在配置时需提供：
  - 意图名称（如 “申请退款”）
  - 用户示例语句（3~10 条，每行一句）
  - 期望参数列表（参数名 + 类型）
  - 是否为默认兜底（仅一个可设为 true）

系统在保存 Workflow 时，自动聚合所有 Output 节点的元信息，构建当前 Workflow 的专属意图空间。

✅ 模式 B：显式意图配置面板（参考 千帆）
- 在意图识别节点内部提供表格/表单，手动添加多个意图：
意图ID   名称   示例语句   参数   关联节点
query_order   查询订单   ["查订单", "我的订单在哪"]   order_id(string)   node_abc

适用于复杂场景或需要跨 Workflow 复用意图的情况。

📌 建议初期采用模式 A（能力驱动），降低用户认知负担。

四、识别引擎实现方案

4.1 默认方案：LLM Zero-Shot 分类（推荐）
- 使用平台统一 LLM（如 GPT-4、Claude、ERNIE Bot、本地部署模型）；
- 动态生成 Prompt，注入当前 Workflow 的意图候选集；
- 强制 JSON Schema 输出，确保结构化解析。

Prompt 模板示例：
你是一个任务路由器。请根据用户输入，从以下可处理任务中选择最匹配的一项，并提取参数。

【可用任务】
{% for item in capabilities %}
- 任务ID: {{ item.id }}
  名称: {{ item.name }}
  用户可能说: {{ item.examples | join("; ") }}
  需要参数: {{ item.slots | keys | default("无") | join(", ") }}
{% endfor %}

请严格按以下 JSON 格式输出，不要任何解释：
{
  "intent": "任务ID 或 'unknown'",
  "confidence": 0.0~1.0,
  "slots": { "参数名": "值" }
}

用户输入：{{ user_input }}

4.2 备选方案（可选）
- 关键词+正则匹配：适用于简单固定指令（如“/help”）；
- 对接 Rasa / Dialogflow：企业级部署时可插拔。

五、UI/UX 需求

5.1 节点外观
- 图标：🧠 或 🔍
- 节点标签：自动显示 “意图识别（N 个意图）”

5.2 配置面板（以模式 A 为例）
区域   内容
意图来源   自动显示：“已关联 3 个 Output 节点”【刷新】按钮（重新扫描）

高级设置   - LLM 模型选择- 超时时间（默认 10s）- 置信度阈值（默认 0.3，低于则视为 unknown）

调试预览   输入测试语句，实时显示识别结果（intent / slots / confidence）

5.3 Output 节点增强配置（关键！）
在每个 Output / Action 节点的属性面板中，新增：
- [输入框] 能力名称（必填）
- [多行文本] 用户可能怎么说（必填，提示：“每行一条自然语言示例”）
- [动态表单] 期望参数（参数名 + 类型下拉：string / number / date / enum）
- [开关] 设为默认兜底能力（全局唯一）

六、执行逻辑（伪代码）

def execute_intent_node(node, context):
    user_text = context["user_input"]
    
    # 1. 获取当前 Workflow 所有 Output 节点的能力描述
    capabilities = collect_capabilities_from_output_nodes(workflow)
    
    # 2. 构建 LLM Prompt
    prompt = render_prompt(capabilities, user_text)
    
    # 3. 调用 LLM
    response = llm_call(prompt, model=node.config.model, timeout=10)
    
    # 4. 解析结果
    try:
        result = json.loads(response)
        intent_id = result.get("intent")
        if intent_id == "unknown" or result["confidence"] < node.config.threshold:
            intent_id = find_default_fallback_capability(capabilities)
    except:
        intent_id = None
    
    # 5. 输出结构化结果
    return {
        "intent": intent_id,
        "intent_name": get_capability_name(intent_id),
        "confidence": result.get("confidence", 0.0),
        "slots": result.get("slots", {}),
        "matched_node_id": get_output_node_id_by_intent(intent_id)
    }

七、错误与边界处理
场景   处理方式
无任何 Output 节点   节点禁用，提示：“请先添加至少一个可执行的 Output 节点”

多个兜底节点   保存时校验失败，提示“仅允许一个默认兜底能力”

LLM 返回格式错误   重试 1 次，仍失败则标记 intent="unknown"

用户输入为空   直接返回 unknown 或兜底

槽位未提取到   slots 为空 dict，由下游节点决定是否追问

八、典型使用流程

1. 用户拖入 Start → 意图识别 → 条件分支；
2. 添加多个 Output 节点（如“查订单”、“退订”、“投诉”）；
3. 在每个 Output 节点中填写 能力名称 + 示例语句；
4. 系统自动在意图识别节点中聚合这些能力；
5. 运行时，用户输入被路由到最匹配的 Output 路径；
6. 下游节点直接使用 {{slots.order_id}} 等变量。

九、与 Dify / 千帆 对标特性
特性   本设计   Dify   千帆
意图来源   Output 节点反推   工具（Tool）描述   显式意图配置

是否需训练   否（Zero-shot）   否   否（支持示例）

槽位提取   LLM 结构化输出   LLM 提取   支持实体抽取

路由方式   输出 matched_node_id   调用对应 Tool   跳转至对应流程

兜底处理   支持默认 Output   支持 fallback   支持默认意图
